# V2.7 manual validation checklist

Run these tests in a disposable GitHub repository before using a valuable project.

## Build and install
- [ ] Open in Android Studio and sync Gradle.
- [ ] Run `:app:testDebugUnitTest` and `:app:assembleDebug`.
- [ ] Install the debug APK on an Android 8.0+ device.
- [ ] Push the project to GitHub and confirm the `Android CI` workflow uploads `mobile-agent-debug-apk`.

## Local Git proposals
- [ ] Clone a disposable repository and create two harmless file changes.
- [ ] Ask the agent to inspect status and propose a commit.
- [ ] Confirm it shows the commit message and explicitly warns that all changes are staged.
- [ ] Reject the proposal; verify no commit was created.
- [ ] Ask again and approve; verify the commit appears in Git status/log.
- [ ] Propose pull and reject it; verify no pull occurred.
- [ ] Propose push and reject it; verify the remote did not change.
- [ ] Approve push with a repository-scoped token; verify the remote receives the commit.

## GitHub Actions workflow dispatch
- [ ] Configure owner/repository and a fine-grained token with Actions: Read and write.
- [ ] Ask the agent to dispatch a harmless workflow on a test branch.
- [ ] Verify the approval card displays the workflow filename and ref.
- [ ] Reject once and verify no run starts.
- [ ] Approve once and verify the API returns accepted and a new run appears in Actions.
- [ ] Confirm an insufficiently scoped token returns a visible failure, not a success message.

## Safety checks
- [ ] Verify tokens never appear in chat history or tool results.
- [ ] Verify no mutation runs before the approval button is tapped.
- [ ] Test malformed workflow names, refs, owner, and repository values.
- [ ] Test with a disposable repo containing merge conflicts; confirm pull errors are visible.
- [ ] Review workflow permissions and repository secrets before enabling dispatch.

The source ZIP was not compiled or device-tested by its creator. These checks are required before relying on the app.
