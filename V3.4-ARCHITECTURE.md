# V3.4 Multi-Agent Architecture

## Orchestration graph

```text
                User task
                    |
                 Planner
                    |
                   Plan
                    |
                  Coder
                    |
             Coder handoff
               /       \
          Reviewer   Debugger
               \       /
             Findings merge
                    |
              Planner synthesis
                    |
               Final report
```

Reviewer and Debugger are independent assessments and execute concurrently. Tool calls are serialized through a shared gateway so that only one approval dialog is active at a time.

## Agent profiles

Each role owns an independent `ApiConfig`:
- protocol: OpenAI-compatible or Anthropic-compatible
- HTTPS base URL
- endpoint path
- model ID
- API key encrypted by `AgentProfilesStore` with Android Keystore AES-GCM

## Shared context

`SharedProjectContext` holds the user task, selected project path, user-provided context and named artifacts. Planner, Coder, Reviewer, Debugger and final Planner synthesis receive the relevant prior artifacts/handoffs. The artifact bus uses a concurrent map because Reviewer and Debugger run in parallel.

## Tool policy

`ToolRegistry` is the permission source of truth:
- `READ_ONLY`: allowed without a dialog
- `USER_APPROVAL`: proposal is shown to the user and execution waits for approval
- `BLOCKED`: rejected by the gateway

The legacy stage-all commit and command execution are blocked in multi-agent mode. Local Git inspection is only enabled when the selected project path is the app's configured `workspace/repository` directory. File operations use a `WorkspaceManager` rooted at the selected project directory, which must remain inside app-private `filesDir/workspace`.

## Trace and token accounting

Every run has a UUID. Events record agent role, lifecycle/tool/approval/handoff type, detail, timestamp, duration and estimated prompt/completion tokens. Room v2 persists run summaries and event rows. Migration 1→2 preserves V1 projects, sessions and messages.

Token counts are estimates from text length (roughly four characters per token). The current HTTP provider adapter does not yet parse provider-specific usage fields, so these estimates must not be used for billing.

## Concurrency and limits

- Planner and Coder run sequentially.
- Reviewer and Debugger run concurrently.
- Shared tool execution is serialized.
- Each agent has a bounded tool-round limit.
- Provider calls use the existing HTTP client's timeout configuration.
- Cancellation propagates out of an agent and cancels the structured-concurrency scope.
